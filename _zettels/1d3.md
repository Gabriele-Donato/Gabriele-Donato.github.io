Variables in C are defined by two properties: **lifetime** (how long the variable is accessible by the program), and **scope** (which parts of the program are allowed to access it). 
Storage class identifiers act on either or both of these variable properties, modifying variable lifetime or scope.

Storage class identifiers are: **auto**, **static**, **extern** and **register**.

1. **auto**

The auto storage class identifier is the default value assigned to variables. The variable using this identifier are scoped within the functions declaring them, and so is their lifetime.
These variables are stored in the **stack** memory.

```c
//The variable:
int var;

//is treated by the compiler as:
auto int var; 

/*
In the below example, the variable lifetime and the scope are limited to the for
loop and the variable will cease to exist and be accessible when the loop ends.
*/

#include <stdio.h>

int main() {
    auto int x = 10;

    printf("Value of x = %d\n", x);

    return 0;
}
```

2. **static**

Static variables are stored in the static storage. The identifier modifies the lifetime of the variable in that its value does not cease to be remembered by the program, but the scope remains the same.

```c

int add_one(void) {
	static int x = 10;
	x++;
}


// Calling the above function three times will yield x=11, x=12, x=13. So the values of x are remembered through the iterations.
// The variable x remains scoped within the function and is not accessible outside of the program.
```


3. **extern**

Extern variables are accessible among different files, the identifier just tells the compiler that within the project there should be a file with the definition of the variable.

```c
//file_1.c
int my_var = 10;

//file_2.c
extern int my_var;
printf("%d", my_var);  //outputs: 10.
```

4. **register**

Back in the day (60' and 70'), it was necessary to manage explicitly the allocation of value from the RAM to the CPU, in order for the latter to perform computations.
The register identifier refers to the explicit passing of variables to the CPU register for better performances. This is no longer in use as compilers have been greatly optimized, and the optimal choices to 
minimize CPU cycles are often non intuitive. In order not to interfere with the compiler optimizations, better not to override its assignments.
