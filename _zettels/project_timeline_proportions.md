Brooks's proportions for software projects are (Brooks p.20):

- $$\frac{1}{3}$$   Planning
- $$\frac{1}{6}$$   Coding
- $$\frac{1}{4}$$   Early Testing (single components)
- $$\frac{1}{4}$$   Final Testing (whole system)

I wonder if the reapplicability comes from the fact that:

1) Any project has roughly the same phases.

2) Maybe I am thinking about similar projects so 1) is false, e.g.  writing a book and writing a software (testing = proofreading).

3) The obvious fact that the setup forces you to devote some time to think about what you want to do.

In general I feel that 3 is correct because forces space creation for each discrete step. It makes the rule quite general and reapplicable.


**References**

- Brooks, P. F. Jr. (1995) The Mythical Man Month. Boston: Addison Wesley.
